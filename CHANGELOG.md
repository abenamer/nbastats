# Changelog

## 0.1.0 — 2026-10-21

- What if page ([ADR 0017](docs/decisions/0017-a-what-if-page-runs-counterfactuals-through-the-season-engine.md)): `/season/whatif`, under the Season menu, runs a real season twice from the same date with the same seed, plain and changed, and shows what moved per team and the changed run's projected bracket. The season engine takes the changes as parameters: `rating_overrides` (a team's rating at the cutoff set by hand), `excluded_teams` (teams barred from the postseason, ordered last in their conference), `qualification` (top eight or play-in) and `first_round_games` (best of five or seven); removing a team is an expansion team's rating of 1,300 Elo and the bar together. The players-out control is shared with the Forecast page.
- Title futures ([ADR 0016](docs/decisions/0016-track-the-title-chances-against-the-sportsbooks-futures.md)): once a day while the regular season runs, the sportsbook's outright prices on the title are read through The Odds API (one credit) and saved per team beside the model's title chance from a forecast of the same day with the injury report; the Model vs Market page shows the latest day's field with the gap per team, the days saved, and, once the postseason is complete, the record of the two against the champion (the Brier score of the field and the log loss, day by day). `GET /api/seasons/{season}/futures`; migration 0009.
- Security review fixes: the server binds to `127.0.0.1:3000` by default for a native run (the image and the compose file set the container's address as before); the BALLDONTLIE client follows no redirect and reads an error body up to 4 KB; the `Debug` output of the configuration and of the BALLDONTLIE adapter redacts the keys; the request guard also rejects every request the browser marks as cross-site to an API path, and a cross-site read of a page or an asset unless it is a navigation to a document, so an image, a script, a fetch or a hidden frame on another page cannot start a read that costs a request to a paid service, and the guard's own answers carry the security headers; the BALLDONTLIE adapter blanks the key in an error message; the masked database URL also masks a password given as a query parameter; the application warns at start when `BALLDONTLIE_BASE_URL` is not https; an upload that cannot be read and a failed dataset download are reported in fixed words, with the detail in the log; two raw table cells escape their values.
- Question box key rotation ([ADR 0015](docs/decisions/0015-mint-and-rotate-the-question-box-key-from-a-management-key.md)): with `OPENROUTER_MANAGEMENT_KEY` set, the application mints its own OpenRouter completion key at start, replaces it every `OPENROUTER_KEY_ROTATION_HOURS` (24 by default) and when the service refuses the key with status 401 (at most once per ten minutes; a 403, its moderation, mints nothing), puts `OPENROUTER_KEY_LIMIT` credits on each, names them with `OPENROUTER_KEY_NAME`, deletes the keys it minted before two minutes after the fresh one is installed and its own at shutdown, and keeps no secret of its own. `OPENROUTER_API_KEY` is optional beside it. `GET /api/ask/status` reports the rotation as times and counts, and `awaiting_key` until the first minted key is in. The compose file passes the four variables to the container.
- Season pages: the Season Forecast page is split in three under a Season menu in the top bar, which opens on hover or focus: Forecast (`/season`) keeps the forecast, the projected bracket, the NBA Cup and the finish charts; Tonight (`/season/tonight`) prices the next night beside the sportsbook's lines; Injury card (`/season/injuries`) prices one team's report, with the season and the team in the address so a card can be bookmarked. Each page has its own home-bonus field and worth what-ifs, and a team code on the Forecast table or the Tonight page opens the team's card. Model vs Market stays its own entry; its head sits level with the other entries. The bet-bar field of the Tonight and Model vs Market pages is laid out as the other fields are, its text above the input.
- Model vs Market: the model version, a string that joins the version of every part, is shown as a short tag (v1, v2…) in the games table, the summary and the note, numbered in the order the versions were first used, with a note under the games table spelling each tag out; the table no longer scrolls sideways for it.
- YAXEL, the emergence term ([ADR 0014](docs/decisions/0014-yaxel-an-emergence-term-backtested-before-it-is-used.md)): a rule that moves a team's rating by what its players' recent box scores say beyond the worth each entered the season with, and a command-line backtest of it over the stored seasons (`nba-elo-simulator yaxel-backtest --from --to [--through] [--new-minutes] [--json]`): two folds of seasons, a grid of window, prior minutes and damping, Brier gain over all games and the early season, with the bar for taking it to a page. Nothing on a page changes yet; the backtest decides. New `domain::yaxel` and `application::yaxel`. The deciding run over 17 seasons (2009-10 to 2025-26) did not clear the bar, so the live term stays off; the run is recorded in the ADR. The backtest then gained the test of the premise: a new-player cut (a player with no line in a stored season before, at least 24 minutes in his team's previous game; `--new-minutes`) with Elo's own Brier score and the bias of those teams against the rating, season by season, and a second run of the grid with the term on the new players alone, both scored on the new-player games as well.
- Dynasty Lab: the "Persistent alpha" field is now "Title tickets (alpha)", with a paragraph on the page saying what it is: a ticket count in each season's title lottery, alpha for the franchise against one for every other, not a rating; the cards, the charts, the season table and the concentration panel name it the same way. The API parameter stays `alpha`. A new panel gives the strength the tickets cannot: the franchise's pre-playoff Elo against the league mean, the best other team and the worst team, its rank, averaged over the window with the range, per season in the table, and the titles read backwards against the real fields as the Alpha Simulator reads them (`strength`, `strength_summary`, `implied` on `GET /api/dynasty`).
- Model vs Market page ([ADR 0013](docs/decisions/0013-call-the-model-against-the-market-by-the-paired-brier-gap.md)): `/market` lists every game the sportsbook priced and the model forecast, with the result, each side's chance, which was the closer, both spreads, the final margin, the moneylines, the lean and the flagged bets, and says in one sentence which of the two has been the more accurate: the paired game-by-game Brier gap, its mean in standard errors, called at two from thirty games on, with the games it takes to get there at the gap and spread so far. The track record carries the `comparison` overall and per group, and lists up to `limit` games (300 by default, 2,000 at most). The Season Forecast page's panel links to the page.
- NBA Cup games from the feed ([ADR 0012](docs/decisions/0012-cup-games-from-the-stage-labels.md)): the results source's Cup stage label on each game (`East Group A` to `Championship`, from 2025-26) is now stored with the game (`cup_stage`, migration `0008`, `domain::models::CupStage` with its round, conference and group letter), and the season engine tells the Cup games of a labelled season by their labels, group, knockout or final, so the 2026-27 Cup and the ones after need no curated dates; the curated dates still tell the games of a season with no labelled game, and stand in when a season's labelled group games do not form the groups while the dated ones do. A Cup season stored before the labels were read is fetched whole on its next results sync, once, so the labels fill in; the daily window then carries each Cup game's label on its day. The Cup note for a season without a forecast names the two remedies.
- Player worth what-ifs ([ADR 0011](docs/decisions/0011-a-worth-what-if-moves-the-team-by-the-difference.md)): the Season Forecast page lets a reader set a player's worth, typed in Elo or read from a window of his last 1 to 82 games (the page offers 1 to 10 and the season so far) through the model's own conversion of a stat line to Elo; his team's rating moves by the difference from the model's estimate and his absences are priced at the what-if, in the forecast (`worth_overrides` in the parameters, kept with the stored forecast), the Tonight panel, its market and the injury card (`worth=id:elo` or `worth=id:lastN` on the request), each answer naming the what-ifs it priced. The model's own numbers and the market tracking do not change.
- Bets the model likes ([ADR 0010](docs/decisions/0010-flag-a-bet-by-its-expected-return.md)): the Tonight panel marks a side's moneyline or spread when its expected return at the sportsbook's price (the model's chance of winning times the payout, less the chance of losing; the price carries the margin) reaches the bar in the new field, five percent of the stake by default, and lists each with its arithmetic in words. Spread chances come from the model's expected margin and the scatter of real margins measured over the played games (`application::market::margin_scatter`). The Model vs market record scores the flagged bets apart (`flagged_*`), at the bar asked for (`min_return` on both endpoints). `domain::market` gains `edges`, `expected_return`, `cover_chances`, `payout`; `Side` moves there.
- Tonight panel: each column now says whose number it holds, the model's (Model spread, Model moneyline, Model wins) or the sportsbook's by its name (FanDuel spread, FanDuel wins), with the sportsbook's columns shaded head and body; Model − market is now Model − FanDuel.
- Market lines from The Odds API ([ADR 0009](docs/decisions/0009-market-lines-from-the-odds-api.md)): with `ODDS_API_KEY` set, the Tonight panel and the market tracking read the chosen sportsbook's moneylines, spreads and totals from The Odds API (`ODDS_API_BOOKMAKER`, FanDuel by default) and fall back to ESPN's scoreboard when a read fails; without a key, ESPN serves as before. The market and each snapshot name their source. The tracking reads by tip-off: on the night's date by the league's calendar (Eastern time), once when the date comes and once in the last eleven minutes before each tip-off time, since only the last capture before a game's start stands; a game night costs about 20 credits at three a read, a month in season 550 to 600. The panel shows the credits left, and the task warns once a night when they do not cover the night's remaining reads. Every "today" the application reads is now the league's date (`domain::calendar`), not the sync zone's. New adapter `OddsApi` and shared feed helpers; `MarketSource` gains `name`; `App::new` takes the keyed adapters in one `Outbound` value.
- Market tracking ([ADR 0008](docs/decisions/0008-track-the-model-against-the-market.md)): the model is now kept against the market. While a market source is on, each game of the Tonight panel that the sportsbook prices and that has not started is saved before its start (at first every ten minutes, now by tip-off, as the entry above says): the model's chances, margin, ratings and penalties, the sportsbook's spread with its prices, its moneylines and its margin-free chance, and the model's version. The last save before the start stands for the game. Once the game is played it is scored: the Brier score and log loss of the model and of the market, the model's lean on the moneyline and its side against the spread at the sportsbook's prices. The Season Forecast page's **Model vs market** panel sums them overall, per model version and per month, with the scored games listed. New migration `0007` (`market_snapshots`), port `MarketStore`, `domain::tracking`, `GET /api/seasons/{season}/market/track` and `MARKET_TRACKING_ENABLED`. Sortable tables now read a value written with a minus sign as a number, so the penalty columns sort by size.
- Availability: a player's worth now pools the seasons it reads. The worth from the missed games combines the season and the two before it: each season's estimate is turned back into what its own games say, the games are added up, and one prior is applied. The box-score worth pools the same seasons by minutes. Before, the box worth came from the latest season alone, so in the first weeks a star was priced off a handful of games: Stephen Curry at 40 Elo, Draymond Green at -1. Each line now names the seasons its estimate draws on.
- Availability: the full-strength rating ([ADR 0007](docs/decisions/0007-full-strength-rating.md)). The season's played games are replayed with the Elo each side was missing in each game (listed on that day's report, absent from the box score) taken out of the expectation, so a loss played short does not lower the rating. The Tonight panel, the injury card, the question box's team tools and a forecast with the injury report price tonight's absences off it, so an absence that has lasted all season is no longer counted twice. The stored Elo stands beside it, with the games played short. A forecast with the report stores `rating_shifts` (season model `elo-season-1.6`). New `domain::full_strength`.
- Season Forecast, Tonight: the sportsbook beside the model. Each team's row shows the sportsbook's spread (with the price of the bet) next to the model's, its moneyline next to the model's, and Market wins: the chance its two moneylines imply once the bookmaker's margin is taken out. Model − market gives the gap in percentage points. The lines come free from ESPN's scoreboard, which the game reports already read (DraftKings lines when ESPN carries them). They are read when the panel loads, one read at a time, kept five minutes (a failed read one minute) and not stored; the note names the sportsbook, the time read and the average margin. New `GET /api/seasons/{season}/tonight/market`, port `MarketSource` (implemented by the ESPN adapter, renamed `EspnScoreboard` as it now serves two ports), `domain::market` and [ADR 0006](docs/decisions/0006-market-lines-from-espn-scoreboard.md). `GAME_REPORTS_ENABLED=false` turns the lines off with the reports.
- Season Forecast, Tonight: the games are laid out as a sportsbook lists them, so they can be read beside one. Each game takes two rows, the visitor on top and the home team under it after @. Each team has its own spread (− gives points, + gets them) and moneyline, then its chance to win at full strength and on the night. The **Reg-season home adv.** field now prices the Tonight panel and the injury card too, not only the forecast. Empty, they use the season's fitted bonus; the note names the bonus used and the fitted one. `GET /api/seasons/{season}/tonight` and the injury card take an optional `home_advantage` in the forecast's range (−100 to 400 Elo) and give `home_advantage_fitted`. The per-column sort key of the shared table goes with the old layout.
- Question box: one call for the whole league tonight. The new `league_tonight` tool returns every team, most hurt tonight first. Each team has its rating, the Elo its absences cost on the next night with games, its mean cost over its remaining games, and who is out (with player identifiers). Each game has its win chances, expected margin and fair moneylines. The prompt sends league-wide questions to it, so a ranking of the most injured teams no longer uses up the budget team by team.
- Question box: tool results are laid out so a cut does not remove part of an answer and its counts. `league_tonight` and `injury_report` stay below the 16,000-character cut. The report gives compact rows with player identifiers: up to 200 lines, with descriptions of 60 characters across the league and 160 for one team, and the number of lines left out. The league tool gives counts in place of lists for its least-hurt teams. The results of one question may add up to 64,000 characters instead of 48,000. The cut note now counts inside the cut. A result longer than the budget left is replaced by a note, not cut in the middle. Refused calls each add a one-line note. The results are sent again on each later model call, so a question can use about 90,000 input tokens of results, a third more.
- Season Forecast, Tonight: each game shows the spread as a sportsbook writes it (the expected margin, 28 Elo to a point, with the home bonus) and both fair American moneylines from tonight's win chance. The columns are named in words and the formulas are explained, so the model's numbers can be compared with a sportsbook's. The games table now uses the full width, above the team table, in place of the two tables side by side.
- Alpha Simulator: points per game use the same 28 Elo a point as the player worth and the spread, in place of 100 Elo for 3.5 points. A gap now shows about 2% more points.
- Data page: one **Update Data** button. It brings the current season up to date in one run: the results and the schedule from BALLDONTLIE with the Elo computed again, then the box scores of every unfetched played date and of the last 2 days, today's injury report and the rosters, one update at a time: the results step holds the results lock, and the player step queues behind a running box-score backfill instead of being refused. A plan without player data ends the player step with a note, not an error. It replaces the results sync button, which read the season to sync from the projection field and so offered the season after the last stored one (2027-28), and the separate box-score, injury-report and roster buttons. The archive import, the projection, the CSV uploads, a past-season sync, the backfill of every season and the player list load move under **Advanced**. New `POST /api/data/update` and `GET /api/data/update/status`; the coverage answer names `current_season`; the season chaining moves from the scheduler to `results_sync::run_chained`.
- Availability: three fixes from one team's card. A questionable player whose return date was tonight's game priced nothing, because the feed's placeholder date equalled the report date; a return date that is the team's next game is now the placeholder for every status, the schedule alone telling it, and the status default applies when no curve does. A star whose team had coped without him in an earlier season priced nothing, because a noisy negative worth from the missed games outranked his box worth under the one-error rule; the box worth is now scaled by the measured share of it that shows up as a team drop (`box-calibration-1.0`, fitted over the players with both estimates, with its error) and combined with the player's own worth by precision, source `blend`. A rookie is now any player with no line in a stored season before this one, whatever his draft year, so a player who lost his first season to injury gets his draft prior.
- Availability: the draft prior. A rookie on the injury report had no worth until he had box scores, so a first pick out for a month cost his team nothing in the forecast. Over the six seasons before, every rookie's first-season box worth is pooled by draft bracket (first pick, picks 2 to 5, 6 to 14, the rest of the first round, the second round, undrafted; 10 rookies minimum, a wider bracket standing in for a short one) into a mean, the error of that mean and the spread. A rookie with no estimate is priced at his bracket's mean with the error of the mean as his error; as his minutes grow his own box worth takes over, the two weighing the same at 500 minutes; a prior within one error of zero prices nothing. New port method `first_appearance_seasons` tells a rookie from a returning player. New pure module `domain::rookie`, the availability answer's `draft` summary and each line's `draft_bracket`, the Players page panel "What a draft slot has been worth as a rookie", and `worth_source` gains `draft`.
- Playoff Simulator and Season Forecast: the full bracket. The bracket is drawn through every round, NBA.com style, each conference's three rounds converging on the Finals in the middle with connector lines. A played series shows its winner and score, one in progress its score, and an unplayed one the team more likely to have won the round before, marked projected, with each team's exact chance of winning the round; the champion box names the likelier finalist with its title chance; a team that has won its way into a round shows its chance from there. The Cup's projected knockout is drawn the same way. Before, only the first round was drawn.
- Season Forecast: the Tonight panel. The next night with regular-season games, each game at the ratings the teams play at that night (the rating less the penalties covering the date) with the home win probability at full strength and as listed, and every team by its rating tonight with who is out and whom it plays. The season average stays in the forecast table; tonight has its own answer. New `GET /api/seasons/{season}/tonight` and `domain::worth::tonight`.
- Season Forecast: the injury card. A team's code in the forecast table, or the team picker under it, opens a card with every line of the latest injury report priced for the team: the worth and its source, the weight and whether it is measured, the penalty per game, the span's end and what set it, the remaining games it covers, the penalty summed over them, its part of the team's mean penalty and the expected wins lost to the line alone (at today's ratings, opponents at full strength). The totals come as listed and with today's absences held to the season's end, so a mean penalty of a few Elo and a team playing tonight a hundred Elo below its rating read as the same facts. New `GET /api/seasons/{season}/teams/{code}/injury-card`, `domain::worth::absence_effect` and `held`.
- Availability: a status is priced for what it has meant, not for what the word says. Every stored injury-report line is followed through the box scores: did the player miss his team's next game, and which of the next thirty. Grouped by status and by the player's state on the report day (not yet out, or already in a run), the lines give each status a measured weight (the share missing tonight) and span (the games missed divided by the weight), which replace the default weight and span from 50 lines on; a status with fewer keeps its defaults. A day-to-day line on a player who had missed a game or two was priced at half his worth for three days and is now priced for what such lines have cost; a line whose return date stands keeps the status's default weight. A completed player sync now drops the caches read from the players, box scores and reports (worth and box tables, return seasons, runs, status samples), which only a results sync or an import did before. New pure module `domain::status` (model `status-curve-1.0`), port method `injury_reports_between`, `span_for` returns the span's weight and what set it, and the availability answer, the Players page (a Weight column and the panel "What a status has meant") and the question box's `team_availability` tool show the curves and which weight priced each line.
- Season Forecast: the held run. **Hold the cutoff date's absences all season** (`hold_absences`) runs the season a second time with every absence covering the cutoff date kept to the last regular-season game, and the team table shows the held penalty, expected wins, playoff and title chances beside the dated ones: the forecast if the roster of the cutoff date were the roster all season, the bound the dated forecast sits above, with the forecast at full strength as the other. Column headers across the pages now show their explanation on hover. The question box's `forecast_effect` runs the same third way for the team asked about and reports the range. The season engine's `SeasonForecast.held` carries the summary.
- Availability: an absence lasts as long as the game logs say, not as long as the feed's placeholder. The injury report's return date is most often the team's next game, so a two-month absence was priced for a day and renewed each morning; the Season Forecast's mean penalty over the remaining games read a few Elo for teams missing a star. Now a return date beyond the next game stands, and otherwise a player listed out, absent, or in a run of three or more missed games is priced for the expected remaining games of a run as long as his, from the survival curve of the runs of regular players over the five seasons before (Kaplan-Meier, runs cut off by a season's end included), laid over his team's schedule. The games missed so far come from the box scores. A regular player absent from his team's last three games who is not on the report is priced as out (status `absent`). A description that says a player is done for the season outranks a day-to-day status. New pure module `domain::spell`; `span_for` in `domain::worth`; the availability answer carries `span`, `missed_so_far`, `listed`, `unlisted` and `survival`; the Players page shows them; the question box's `team_availability` names them.
- Players page: return from absence. A report of what regular players deliver after a run of five or more missed team games, against the twenty team games before: box worth per game played, BPM, minutes, share of the floor and availability, in the first ten games back and the next ten, grouped by the player's BPM before the run (below 0, 0 to 2, 2 to 5, 5 and up) and by the run's length (5 to 9, 10 to 19, 20 to 39, 40 and more). The control is every clean forty-game stretch of a regular player, grouped by the same BPM rule, so the fall two windows show without an injury (largest for the players who were playing best) can be taken off. The report changes no rating, penalty or forecast; it is the measurement a return ramp in the engine would rest on. New pure module `domain::recovery`, use case `application::recovery` (one season computed once and cached), `GET /api/research/return-curve` (one report at a time).
- Question box: `team_availability` counts a game dated today without a result among the remaining games, as the forecast does, and names the schedule's size and the games played. In an NBA Cup season, `team_games` and `team_availability` say when a schedule holds fewer than 82 games: the league adds the Cup-week games in December, and the prompt tells the model to repeat it. An 80-game schedule and tonight's game no longer read as missing games. The rule lives in `domain::cup::games_to_be_scheduled`.
- Season Forecast: an absence no longer slides the simulated rating. The rating update of a simulated game now expects the penalized sides, as the result does. A known absence therefore moves the standings and not the rating, and the team plays at its full rating from the day the absence ends. Before, the team under-performed its rating through the absence and finished the season under-rated. A two-month absence then cost about twice the wins the arithmetic supports: 14.6 wins for the Warriors' injury report that ends in January. The team table gains the rating each team plays at on the cutoff date, beside the mean penalty. The page defaults to today's date for the season in progress and to the preseason for a past season. The Elo column and the question box then agree. The question box names the date a rating stands at. `TeamForecast` gains `absence_penalty_today`; the season model version is `elo-season-1.5`.
- Question box: players and availability. Six new tools let the box answer about the stored players. `find_player`, `player_worth` (both estimates per season, the latest three by default), `season_worth_leaders` and `injury_report` read the players. `team_availability` gives a team's current rating, its report lines priced, the Elo it plays without today and the mean penalty over its remaining games. `forecast_effect` runs the season engine twice from today, with the report's absences and with the team's own absences removed, once per question. The question "if the Warriors had everyone healthy, what effect would it have on their Elo?" is now answered from the data. The scope and the refusal sentence name players, box scores and injury reports; coaches, awards and contracts stay out. Player names, injury statuses and the start of a description now travel to the model's provider; the concept and the security model say so. New `application::ask_players` behind the `PlayerLookups` trait; `ask::answer` takes it.
- Season Forecast: players marked out. A **Player out** control adds an absence by hand: a player found by name, a span of dates and an estimate. The estimate is the player worth with its error, the box-score worth, or whichever exists. One span per player. A player marked out replaces his line in the injury report when the report is used too. With **Draw each worth from its uncertainty**, every simulated season draws each absence's penalty from its standard error, held between zero and the cap. The forecast's spread then reflects how little is known about a worth. The reported penalty is the mean of the held draw, and an error of zero is the fixed case. The injury report now prices a player whose worth from the missed games is within one error of zero, or who has none, with his box-score worth. The Players page shows each line's error and source. `Absence` gains `se_elo`, the request gains `sample_worth` and the result gains `absences_sampled`. Two overlapping absences of one player are refused. The rows of `GET /api/players/{id}/worth` name their season and teams, and the availability lines carry `se_elo` and `worth_source`. The season model version is `elo-season-1.4`.
- Players page: box-score worth. Beside the worth read from the games a player missed, every player who played gets a second figure from his box score: Box Plus/Minus 2.0 (Daniel Myers's published method, computed by the application from the stored lines: per-100-possession statistics weighted by the estimated position and offensive role, with each team's players summing to its schedule-adjusted efficiency), offensive and defensive BPM, VORP over a replacement level of -2.0, wins over replacement and PER. The box worth is BPM over replacement by the share of the floor in the games he plays and the team's pace, on the Elo scale (28 per point), shown as a column beside the player worth and in its own table. The raw-BPM step of the published worked example reproduces within the rounding of its lines. Seasons without the rebound split, steals or blocks get PER only; seasons without turnovers get them imputed, as the published method does for 1974-77. New pure module `domain::bpm`, use case `application::boxscore`, port method `PlayerStore::season_box_lines`, route `GET /api/seasons/{season}/box-worth`; `GET /api/players/{id}/worth` gains `box_seasons`.
- Players page: player worth and availability. Each player's worth to his team's rating, from the games the team played without him: the game residuals are regressed on the absences of both sides with a prior toward zero whose spread is estimated from the data, giving a worth in Elo with a standard error. The latest injury report is priced the same way, by status and return date, and the Season Forecast takes it off each team's rating for the games to come when **Use the injury report** is ticked; the team table shows the penalty and the stored parameters hold the absences. New pure module `domain::worth`, use case `application::worth`, routes `GET /api/seasons/{season}/player-worth`, `/availability` and `/api/players/{id}/worth`, forecast parameter `absences`, request flag `use_injury_report`; the season model version is `elo-season-1.3`.
- Player data: backfill every season on its own. A run over every season fetches the box scores of every unfetched date from a first season to the current one, newest first, skipping complete seasons. A season whose run stops does not stop the others. **Backfill every season** on the Data page, `POST /api/data/players/backfill-all` and `backfill-players <season> --every-season` start it. With `PLAYER_BACKFILL_FROM` set, a background loop backfills season by season until nothing is left. A season whose run stopped is tried again ten minutes after the pass. The loop survives restarts (the fetch records are the bookmark), lets the daily sync run between seasons, and stops when the source rejects the key, tier or path. The Data page lists the seasons still missing box scores, and the status line names the season under way. Compose now passes `PLAYER_SYNC_ENABLED` and `PLAYER_BACKFILL_FROM` into the container.

- Backtest: series scored one by one. Every played series is a trial, scored on the model's probability for its two actual participants with the series' actual home court (two-sided Brier, log loss, whether the favourite won), overall and by round, with the paired difference against the first model of the run; the favourite's calibration joins the calibration panel, the season table carries the series totals, and the rolling tuning minimises the series log loss (`tuning.criterion`, default `series`; `champion` keeps the old criterion); a model with a K-factor, which has no exact probabilities, is refused instead of failing the job. With 315 series instead of 21 champions the models separate: the log5 model on regular-season record beats Elo by 0.037 in log loss (two standard errors of the paired difference), Elo is under-confident in the first round and over-confident in the conference finals, and rolling tuning gains nothing. - Alpha Simulator: the question in reverse.
