# Purpose

The Tonight page sets the model's numbers beside a sportsbook's for the coming night. Market tracking keeps them, so that once the games are played the model can be judged against the market: on its chances, and on the bets its disagreements would have made. Each saved game carries the model's version, so a change to the model starts a new record instead of blending into the old one.

# Capture

While the application runs with a market source, a background task reads the Tonight page's night of the current season and its sportsbook lines, at the times that matter: once when the night's date comes, to learn the tip-off times, then once in the last eleven minutes before each tip-off (the task looks every ten minutes, and the extra minute keeps a tip-off that falls between two looks on the earlier one). The source is The Odds API with the sportsbook of `ODDS_API_BOOKMAKER` (FanDuel by default) when `ODDS_API_KEY` is set, with ESPN's scoreboard as the fallback when a read fails, else ESPN's scoreboard alone ([ADR 0009](/decisions/0009-market-lines-from-the-odds-api.md), [ADR 0006](/decisions/0006-market-lines-from-espn-scoreboard.md)). `MARKET_TRACKING_ENABLED` turns it on by default; any value other than `1`, `true` or `yes` turns it off. Viewing the page starts no capture. The task reads only when the night is today by the league's calendar (Eastern time): only the last capture before a game's start stands, and every game of a date tips off on that date, so a read on another day, or between tip-offs, buys nothing and costs the service's credits. Two games with the same tip-off time share one read. A read that got no answer records nothing, so the next look tries again (the source's one-minute failure memory keeps the tries apart); a read that priced none of the night's games, or priced a game without a start time, is tried again after an hour, since the sportsbook posts its lines hours before a game. A day with no game to read is marked once, so the looks that follow cost nothing until the date changes. A game the sportsbook prices late gets its tip-off time from the next read, if one is still to come; one priced after the night's last read is not stored. For each game the sportsbook prices that has not started, it saves a snapshot (`domain::tracking::Snapshot`):

* the model's home chance at full strength and on the night, its expected home margin on the night, the full-strength and stored ratings, the penalties of the night and the home bonus;
* the sportsbook's spread for the home team with the price of each side, both moneylines, the total, the home chance its moneylines imply with the margin taken out, and that margin;
* the sportsbook, the source (`the-odds-api` or `espn`), the game's start time, the time the lines were read, the model version and the application version.

The model version joins the versions of the parts that make the night's numbers: the full-strength rating, the pooling of a player's worth, the box calibration, the box-score worth, the conversion of a rating gap to points, the status curves, the spell curve and the draft priors. The string is long, so the Model vs Market page shows each distinct version as a short tag (v1, v2…), numbered in the order the versions were first used with the version saving now last when nothing is stored under it yet, and spells the tags out in a note under the games table. A snapshot is keyed by date and team codes, as the game reports are, so a re-import of the games keeps it. A later capture replaces an earlier one only while the game has not started: before the capture's own start time when it has one (a moved tip), else the stored one. A capture without a start time keeps the stored start. The last capture before the start stands for the game. That line is within about sixteen minutes of the closing line: the read comes in the last eleven minutes before the tip-off, and the lines may be five minutes old from the cache. Neither source serves past games' lines without cost, so the live record starts on the day tracking is first on; the nights before can be filled from The Odds API's history on a paid plan (see Backfill below). The Odds API bills a credit per market in each read, three a read here; a game night costs a read for the night and one per distinct tip-off time, about six on a full night, so about 20 credits; the league plays on about 28 nights a month in season, so a month is about 550 to 600 credits before page views. The free 500 credits a month run out in a full month's last days; the smallest paid plan covers it. Page views of the Tonight page add a read when the five-minute cache has run out. The adapter keeps the credit count from each answer; the Tonight page shows it, and the task warns once a night when the credits left do not cover the night's remaining reads.

# Backfill

The nights the live capture did not see, the games before the tracking was on and the seasons before, can be filled from The Odds API's history ([ADR 0018](/decisions/0018-backfill-the-market-record-from-the-sportsbooks-history.md)), which holds the featured markets from June 2020, at ten-minute intervals and at five-minute intervals from September 2022; the service serves it on a paid plan only, at ten credits per market in a read and one per listing. The command `market-backfill` ([runbook](/runbooks/market-backfill.md)) takes a range of dates and, for each night in it with stored regular-season games that have no snapshot, reads the night's tip-off times as the service listed them at ten in the morning Eastern (the `MarketHistory` port, implemented by `adapters::odds_api::OddsApi`), then the lines as they stood fifteen minutes before the night's first tip-off, or before each tip-off time with `--per-tip-off`, the latest snapshot at or before that time; the snapshot's own time is the capture's. A read asks for every sportsbook of the US region at the same price, and a game takes the configured sportsbook's line when it has one, else the first sportsbook with a moneyline, the row naming its sportsbook and the source `the-odds-api-historical`. The games are matched to the stored games by team as the live lines are, and saved by the same rule, so the last capture before a game's start stands: a live row is never replaced, and a night whose games all have a snapshot costs nothing on a later run.

The model's side of a backfilled row is the stored pre-game Elo alone, with the season's fitted home bonus and no absence priced, under its own model version, `elo-stored-1.0` with the margin model: a past night has no injury report to price as the live model prices tonight's, and the record's per-version summaries keep the two apart, while the overall summary mixes them. The expected margin, the lean, the side against the spread and the flagged bets are scored as for any row. A dry run (`--dry-run`) lists the nights and the estimated cost. A run counts its requests' cost by the service's rates and stops before a request that would pass `--max-credits` or that the credits left at the service do not cover, when the service refuses a request, or when five nights fail in a row; a night gets at most sixteen reads; the answer says where and why it stopped. The record was backfilled on 2026-11-05 for every game from 2020-21 to 2025-26 but two, at one moneyline read a night, and for the 92 games of 2026-27 before the tracking was on at every tip-off time with the three markets; [ADR 0018](/decisions/0018-backfill-the-market-record-from-the-sportsbooks-history.md) records the runs and what the record then says.

# Scoring

Once a game's result is stored, its snapshot is scored (`domain::tracking::score`):

* **Brier score**: the squared difference between the home chance and the result (1 for a home win, 0 for a loss), for the model and for the market. Lower is better.
* **Log loss**: minus the logarithm of the chance each gave to what happened. Lower is better, and it punishes a confident miss harder than the Brier score.
* **Lean**: the side whose chance the model puts above the market's. Its result is a one-unit bet on that side at the sportsbook's moneyline: a win at +114 returns 1.14 units, a win at -135 returns 100/135, and a loss costs one unit.
* **Against the spread**: the side the model's expected margin takes against the sportsbook's line, bet at that side's price (-110 when the price is missing). A push returns nothing.
* **Flagged bets**: the bets the edge rule ([ADR 0010](/decisions/0010-flag-a-bet-by-its-expected-return.md)) marks on the stored line, each scored at its price: a moneyline or a spread side whose expected return (the model's chance of winning times the payout at the posted price, less the chance of losing) reaches the bar, five percent of the stake by default and `min_return` on the request. The spread chances come from the model's expected margin and the measured scatter of real margins (about 12 points), measured over the whole season and its window when the record is read, so the scatter a past bet is scored with can differ a little from the one the panel showed that night. These are the bets the Tonight page would have marked, so their record judges the highlights.

A tie scores nothing. A snapshot whose game is not yet played is pending; one that matches no stored game (a game moved to another date), or whose stored score is a tie, is counted apart as unmatched. The three counts add up to the snapshots. The track record (`application::tracking::record`, `GET /api/seasons/{season}/market/track`) sums the scored games overall, per model version and per month, the flagged bets included; it carries the bar and the scatter it was scored with. The Brier and log loss means of the model and the market are over the same games: those the sportsbook priced. A return above zero per bet beats the sportsbook's margin. The Season Forecast page shows the record in its **Model vs market** panel, with the latest scored games; the **Model vs Market** page (`/market`) shows the verdict below and every scored game of the season (`limit` on the request, 300 by default, 2,000 at most).

# Which is more accurate

The two forecasters are compared game by game on the games both priced ([ADR 0013](/decisions/0013-call-the-model-against-the-market-by-the-paired-brier-gap.md), `domain::tracking::compare`). The gap of a game is the sportsbook's Brier score less the model's, so a positive gap favours the model. The comparison gives the mean gap, its standard error (the sample standard deviation of the gaps over the square root of their count) and the mean in standard errors; the games each side was the closer on, and the level ones; the leader, the side with the lower mean score; whether the lead is decided, at two standard errors or more, about one chance in twenty of luck alone, and from thirty games both priced on, since fewer cannot carry the normal approximation the test rests on; and how many games it takes to reach two at the mean gap and spread seen so far, the square of twice the standard deviation over the mean gap, at least thirty, reported as none beyond ten seasons' worth (12,300); a lead is decided exactly when the games reach the figure. One game has no error; games with the same gap every time have an error of zero and no verdict; a mean gap too small to tell from zero is level, with no leader; without a game both priced there is no comparison. It is made overall, per model version and per month, and travels with the track record as `comparison`. The page puts it in one sentence: who has been the closer, the two mean scores, the count, the lead in standard errors, and whether it is more than luck gives, with the games to tell when it is not.

The comparison treats the games as independent. Games of one night share the injury report and the ratings, so the standard error is a little understated; the bar of two errors leaves room for that. Log loss is shown beside the Brier score and not called.

# Title futures

The season forecast's headline is each team's chance of the title, and a sportsbook prices the same thing as championship futures, the outright prices on every team ([ADR 0016](/decisions/0016-track-the-title-chances-against-the-sportsbooks-futures.md)). Once a day while the regular season runs, at the day's first look of the capture task, the application reads the sportsbook's outright prices through The Odds API (one credit; ESPN's scoreboard carries none, so the futures need `ODDS_API_KEY`) and forecasts the season from that day with the injury report, from the full-strength ratings, at 2,000 simulated seasons with a fixed seed, as the question box's comparison runs it (`application::futures`). Both chances are saved per team and day (`futures_snapshots`): the sportsbook's price, the chance it implies with the field's margin taken out by the proportional rule (every implied chance scaled by the same factor so the field adds up to one, `domain::market::fair_field`), the margin, the model's chance with its simulation error, the model version and the application version. A later capture of the day replaces an earlier one. A read or a forecast that fails is tried again after an hour; an answer the application cannot keep (the sportsbook prices no title or names no team of the season, or the answer is not an outright listing) waits for the next day, so a configuration that cannot work costs one credit a day. The field is the season's teams the sportsbook names; a name it does not match is left out and logged. The capture runs from the day the season's schedule is stored to its last regular-season game; the playoffs are not captured, since the season engine forecasts from before them.

Once the postseason is complete, each saved day is scored against the champion (`domain::futures::score_days`): the squared error summed over the teams, the Brier score of the field, and minus the log of the chance given to the champion, for the model and for the sportsbook; lower is better. The record counts the days each was the closer and gives the mean scores. The days are not independent, so no standard error is put on the count; the judgement firms up over seasons. The Model vs Market page shows the latest day's field, the model beside the sportsbook with the gap in percentage points, the days saved and the record (`GET /api/seasons/{season}/futures`).

# The betting portfolio

The Bets page (`/bets`, `GET /api/market/bets`, `domain::betting`, `application::betting`) reads the same record as a stock portfolio: a pot on a start date, a bet on every scored game, and the pot's path. Seven strategies run side by side. Three lay the base stake on a favourite: the sportsbook's (the side its margin-free chance puts at one half or above), the model's (the side the model's chance does), and the model's on the games where it is not the sportsbook's, with no bet on the rest. Two size the stake by the gap between the model's chance and the sportsbook's and bet the model's lean, the side the model rates above the sportsbook: the stake is the base stake times the gap over a reference gap (5 points of chance unless set), once in proportion and once squared, so at twice the reference gap the first lays twice the stake and the second four times; a game the two price alike is not bet, and the sized stakes have no cap. Two more lay the same sized stakes on the model's favourite only on the games where it is not the sportsbook's, the disagreements, which is the lean on those games. Each strategy runs at the posted prices and at the fair ones. A win at the posted price returns the stake times the moneyline's payout (`domain::market::payout`); a loss costs the stake. At the fair price a win on a side the sportsbook gives the chance p returns the stake times (1 − p) / p, the margin-free moneyline, so the margin's cost reads apart from the forecasts' worth. The pot is the running sum of the returns, so a run never stops for want of money and the path is the running total of the bets. The page takes the start date (the record's first game unless set), the pot ($10,000), the base stake ($100) and the reference gap, and shows, at the prices chosen, each run's final pot, net, return on the pot, bets, money staked and largest stake, peak and largest drawdown (the fall from a peak to a later value), the path day by day, the net in standard errors (the spread of the bets' returns times the square root of their count), and a row per season with each strategy's bets, wins, money staked and net. The games are those the record has scored over every season with a snapshot, in date order; a scored game without a sportsbook chance or a moneyline for both sides is left out and counted, as are the games before the start date. The sportsbook named is the one most of the lines come from, with the games it priced; the backfilled nights it did not price carry another sportsbook's line. The caveats of the record hold: the backfilled seasons carry the stored Elo alone against a line read once a night, and a game priced at exactly even counts as a home favourite.

# Limits

* A few dozen games say little: the return of a bet has a spread of about one unit, so a season of a thousand games puts the error of a mean return at about three cents a unit. The Brier difference settles sooner.
* The lines are one sportsbook's, read up to about fifteen minutes before the start; a line that moved in the last minutes is not seen.
* Two rare cases keep an older line: a game pushed later in the night whose later captures carry no start time stops at the first start, and a start corrected to earlier than a stored capture leaves that capture in place.
* The model's numbers are those of the moment of the capture. A model change made since does not rescore old games; the version on each row says which model made it.
* A record that spans both sources mixes two sportsbooks' lines; each snapshot names its sportsbook and source, so the rows can be told apart, but the summaries do not split them. A backfilled row read once a night carries, for the night's later games, a line hours before their start, nearer an opening line than a closing one; and its model side is the stored Elo alone, which the version tag says.
