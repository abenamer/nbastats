| Method and path | Function |
|-----------------|----------|
| `POST /api/jobs/alpha` | Queue an Engine A run. Body: `AlphaParams` (`franchises`, `alphas`, `seasons`, `iterations`, `threshold`, `seed`, `target_index` defaulting to 0 for the franchise of interest, and an optional `schedule`, a seasons × franchises alpha table that replaces `alphas` season by season) plus optional `name`. |

| `POST /api/jobs/season` | Queue an Engine C run. Body: `SeasonParams` plus optional `name`. With `hold_absences` true, the season runs a second time with every absence covering the cutoff date and ending before the last regular-season game held to that game, and the result's `held` carries `absences_held`, `held_to`, `elapsed_ms` and `teams` (per team `team_id`, `code`, `absence_penalty`, `expected_wins`, `p_top6`, `p_play_in`, `p_playoffs`, `p_conf_finals`, `p_finals` and `p_champion`, in the held run's order: join on `team_id`); `held` is null when nothing was held. The stored `params` are the dated ones with the flag. The work estimate doubles with the flag. See the [season engine](/concepts/season-engine.md). The result carries, per team, `seed_distribution` (the chance of each playoff seed, 1 to 8) beside `position_distribution`, and `projected_bracket` (the most likely bracket seed by seed, with `exact` stage probabilities per slot at fixed ratings, `first_round` series as `slot_a`, `slot_b`, `p_a`, and the counts `exact_count`, `field_count` and `most_common_count` over the `sampled` seasons, the first 200,000, with their shares `p_exact`, `p_field` and `p_most_common`; null when no simulated season reached the playoffs; absent in results stored under model version 1.0). For a season with an NBA Cup, `cup` carries the groups with their tables so far, each team's chances (`p_knockout`, `p_semifinal`, `p_final`, `p_winner`), the projected knockout bracket (`slots`, `exact` chances per slot, `quarterfinals`, and the counts over the sampled seasons) and `actual_winner`; otherwise `cup` is null and `cup_note` says why (model version `elo-season-1.2`; earlier results have neither). See the [NBA Cup forecast](/concepts/nba-cup.md). `home_advantage` is the playoff bonus; `regular_home_advantage` (optional, -100 to 400) prices the regular-season and play-in games and takes the season's fitted value when absent, which the stored parameters then show; status 500 when the store cannot be read.  `absences` may be given directly (`team_id`, `from`, `to`, `elo`, optional `player_id`, optional `se_elo`), at most 500, each at most 400 Elo and 400 of error. Two absences of one team add up; two of one player with overlapping spans answer 400. With `"use_injury_report": true` the latest injury report is added after the given absences (see [Player worth](/concepts/player-worth.md)). A given absence with a `player_id` replaces that player's report line. More than 500 in all answer 400 naming the report's share. With `"sample_worth": true` each absence keeps its `se_elo` and the engine draws its penalty in every simulated season. Otherwise the errors are set to zero and the penalties are fixed. The result carries `absences_applied` and `absences_sampled`, and per team `absence_penalty` (mean over its remaining games) and `absence_penalty_today` (on the cutoff date). Model version `elo-season-1.5`: the rating update of a simulated game expects the penalized sides, so an absence moves the standings and not the rating.|

# Example

    curl -s -X POST http://localhost:3000/api/jobs/alpha \
      -H 'Content-Type: application/json' \
      -d '{"name":"equal","franchises":["A","B","C"],"alphas":[1,1,1],"seasons":10,"iterations":100000,"threshold":3,"seed":1,"target_index":0}'

Poll `GET /api/jobs/{id}` until `status` is `completed`.

# Errors

Errors return JSON `{"error": "message"}` with status 400 (bad input), 403 (cross-site request), 404 (not found), 409 (conflict), 421 (host not allowed), 429 (too many questions at once), 502 (the language model service failed), 503 (database unavailable, or the question box not configured) or 500 (internal, details only in the log).
